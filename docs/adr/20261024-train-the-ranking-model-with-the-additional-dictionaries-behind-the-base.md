# 並べ替えのモデルは、配る追加辞書を基本辞書の後ろに並べて学習する

状態：採用

## 背景

並べ替えのモデルを使うと、追加辞書の候補が基本辞書の候補より上に来ていた。何もない入力欄で「はこ」を変換すると、モデルなしでは 箱、ハコ、匣、筺、函 … と基本辞書の候補が続き、絵文字はその後ろに回るが、モデルありでは 箱、ハコ の次に 🗃️ 📥️ 📦️ 🎁 📤️ 🧰（絵文字）と 葉子（人名）が来て、匣、筺、函 はその後ろになった。ほし、ねこ、やま、あめ でも、絵文字・記号・顔文字が基本辞書の語の間に入った。

候補の違いを決めているのは、ほぼコストの特徴（`c|cost/50`、`cw|cost/200`、`dc|辞書の位置|cost/200`）と表層の特徴（`s`、`rs`）で、追加辞書の候補の特徴は、どれも学習で一度も現れていなかった。

- 学習のエンジンは、学習用の文書だけの基本辞書しか持たなかった。追加辞書の候補は、選ばれなかった候補としても例に出てこない。
- 学習する辞書の位置はいつも 1 だった（位置 0 は利用者の custom 辞書）。`dc|k|*`（k ≠ 1）はどれも学習されていない。
- 学習用の文書だけの基本辞書には、コスト 7400〜8599 の語がない。記号・絵文字・顔文字のコスト（8192 から）の段は、どの特徴でも学習されていない。

学習していない特徴の重みは、ハッシュで当たったほかの特徴の重みで、0 に近い。普段負ける基本辞書の候補は、学習で大きな負の重みを持つ。コストの段は一つずつ独立していて大小の順を持たないので、学習していない 0 付近の段が、負けると学習した負の段より上に来る。

記号・絵文字・顔文字のコストを 8192 から始めたのは、Kanaemi がコストを 2 を底とする対数の幅で見ていたころ（モデルの形式 3）の前提による。そのころ 8192〜16383 は、基本辞書の裏付けのない漢字と同じ幅で、その幅は負に学習されていた。コストを一定の幅の段で見るようになって（形式 4）、8192 は学習データのない段に入った。

## 決定

- 並べ替えのモデルの学習で、学習用の文書だけの基本辞書の後ろに、`additional/` のすべての追加辞書を並べる。追加辞書は、学習用の文書だけの基本辞書に対して作ったもの（`just additional --train-only`、`build/dictionaries/train/`）を使う。評価用の文書の記事を素材から除いて作ったもので、配るものと同じく、基本辞書が持つ行を持たない。
- 追加辞書の並びは文書ごとに変える。名前の順に並べた追加辞書を、文書 ID のハッシュを追加辞書の数で割った余りだけ回して並べる。打つ人は追加辞書をどの順にも並べ、いくつ入れるかも人による。どの追加辞書もどの位置にもほぼ同じだけ来るようにして、`dc|k|*` が特定の辞書の並びを覚えないようにする。同じ文書はいつも同じ並びになり、学習し直しても同じ例ができる。
- 記号・絵文字・顔文字のコストは 8192 からのまま変えない。モデルなしでは、Kanaemi は辞書の位置を先に、コストを後に見るので、コストは追加辞書の中の並びにしか効かない。モデルありでは、その段の重みを記号・絵文字・顔文字そのものから学ぶ。`symbols.rs` のコメントを、この見方に直す。
- `just ranking` は、基本辞書だけで測ったあと、学習のときと同じ追加辞書を名前の順に後ろに並べて、モデルなしとありでもう一度測る。モデルが追加辞書の候補を基本辞書の候補より上に上げないかを、毎回見るため。

## 検討した他の案

- 追加辞書を名前の順だけで並べて学習する：評価で並べる順と同じなので、評価の数字は良く出るとみられるが（測っていない）、`dc|k|*` が名前の順の辞書の並びを覚える。打つ人の並び（issue の例では custom, base, it, games, science, place, 2026, emoji, emoticon, symbol, person）では、位置ごとに別の辞書の重みが当たる。
- 記号・絵文字・顔文字のコストを、学習で負になっている段（16200 以上など）に選び直すだけにする：記号・絵文字・顔文字は後ろに回るが、人名・地名・駅名や分野の辞書の候補は変わらない。人名の 葉子 は、コストが基本辞書の語と同じ段に入り、学習していない `dc|k|*` と `s`・`rs` の重みで点が付く。負の段の重みは基本辞書の裏付けのない漢字から学んだもので、記号の候補の振る舞いを学んだものでもない。
- Kanaemi に、学習した辞書より後ろの辞書を表す特徴を足すか、コストの特徴に大小の順を持たせる：モデルの形式が変わり、Kanaemi の本体を変える必要がある。学習で追加辞書を見せれば、今の形式のままで直る。学習で見ていない追加辞書（新しく足したもの）にはこの案が要るので、そのときに改めて決める。
- 学習の例で、文書ごとに入れる追加辞書を選び、入れる数も変える：打つ人が入れる辞書の数の分布が分からない。すべてを並べても、位置ごとの重みは回すことで均され、少ない辞書を入れた人の位置（2〜5 など）も、どの辞書でも学習される。

## 結果

評価用の文書の全単位の損失を、配っていたモデル（基本辞書だけで学習したもの）と、追加辞書を並べて学習したモデルで比べた（2026-10-24）。「＋すべての追加辞書」は、学習用の文書だけの基本辞書の後ろに、それに対して作った追加辞書を名前の順に並べたもの。根拠は [評価で決めた辞書の値](../references/evaluation-experiments.md) の「追加辞書を並べて学習する」。

| 辞書 | モデルなし | 基本辞書だけで学習 | 追加辞書も並べて学習 |
| --- | --- | --- | --- |
| 基本辞書だけ | 21,820 | −11,903 | −11,610 |
| ＋すべての追加辞書 | 22,433 | 6,944 | −10,240 |

- 追加辞書を並べたときの損失は 6,944 から −10,240 になり、基本辞書だけのときとの差は 18,847 から 1,370 に縮む。1 ページ目（9 位まで）の損失は 6,871 から 2,582 になる。
- 基本辞書だけの損失は 293 増える。読みごとの増減は、1 位の数が増えた読みと減った読みが入り混じる（増えたのは合わせて 2,456、減ったのは 2,752）。学習する候補が増え、重みの位置の衝突が増えたためとみる。
- 何もない入力欄の「はこ」は、箱、ハコ、匣、葉子（人名）、筺、函 … となり、絵文字は基本辞書の候補より後ろに回る。ほし、ねこ、はれ、やま、かき、あめ でも、絵文字・記号・顔文字は基本辞書のよく使う候補の後ろになる（ほし の 乾、やま の 岾 のようなまれな漢字 1 字よりは前に来るものがある）。からい は、記号の 辛 が 1 位だったのが、基本辞書の 柄井 になる。
- 人名の 葉子 は、匣 の次に残る。葉子 は基本辞書に ようこ の読みでよく出る表記で、読みを見ない表層の特徴（`s`）の重みが大きいためとみる。
- 正解集（`just check-words`、`--with person emoji symbol emoticon` も）の数字は変わらない（モデルありで、前の文のある語の 1 位が 904 語中 532）。確かめの一覧の期待どおりでない項目も 4 のまま。
- 学習の例は 3,988 万件から 4,256 万件になる。
